# public-data/

公共参考数据包。**这里的数据不是本项目的原创内容**，各自有独立的来源与许可要求。
postmarkTrip 本身是 [MIT](../LICENSE)，但**这不改变**下述数据的使用条件 ——
分发或再使用这些数据时，你必须一并遵守它们各自的许可。

## 为什么单独一个目录

对应架构上的 **L2 层（公共实体）**（见 `docs/ok/04-环境约束与多语言架构选型.md` §4）：

| 层 | 内容 | 位置 |
| --- | --- | --- |
| L0 | 原始扫描件 | 本地 `data/assets/`（不可变） |
| L1 | 你的私人记录（卡片、邮戳实例、备注） | 本地数据库 |
| **L2** | **邮戳条目、邮票条目、邮局名录、行政区划** | **本目录 + 云端数据包** |
| L3 | 你把自己确认过的条贡献回 L2 | 导出/导入 |

所以这里的文件是**可替换、可重新导入**的：删掉不会丢失你的私人收藏，重新导入即可恢复
（见 `docs/ok/05-部署架构与安装指南（规范）.md` §三）。

> 在数据就位之前，界面上的地点树与邮局列表会是空的 —— 这属于预期状态。

## 一、行政区划

### 全球

| 项 | 内容 |
| --- | --- |
| 来源 | **GeoNames** |
| 链接 | <http://download.geonames.org/export/dump/readme.txt> |
| 许可 | **CC-BY 4.0** |
| ⚠️ 硬性要求 | **必须署名**。这是 CC-BY 的核心义务，不是可选项。 |

补充：多语言地名可另接 **Unicode CLDR**（多语言名称是它的专长）；地图底图与边界矢量可用
**Natural Earth**（public domain）。ISO 3166-1 / 3166-2 用作**主键编码**，
但其批量数据本身不免费，因此数据实体仍取自 GeoNames/CLDR。

### 中国

| 项 | 内容 |
| --- | --- |
| 来源 | **民政部**《中华人民共和国县以上行政区划代码》 |
| 链接 | <https://www.mca.gov.cn/mzsj/xzqh/> |
| 来源 | **国家统计局**《统计用区划代码和城乡划分代码》（到乡镇/村） |
| 链接 | <https://www.stats.gov.cn/> |
| 开源数据包 | **`modood/Administrative-divisions-of-China`**（省/市/区县/乡镇/村 五级） |
| 链接 | <https://github.com/modood/Administrative-divisions-of-China> |
| 许可 | 见各上游仓库自身声明（本项目仅作数据搬运与格式转换） |

**关于直辖市**：本项目的 `place` 表是自引用树，**不硬编码层级数**（见 `db/models.py`）。
北京市如实存为「北京市（省级）→ 东城区（县级）」，**中间层留空** ——
不做「北京市-北京市-东城区」那种把地级层填成同名的取巧（见 `docs/need/03` §五）。
因此筛选要按 `level_label` 而不是"第几层"。

## 二、邮局名录

| 项 | 内容 |
| --- | --- |
| 来源 | **国家邮政局「邮政普遍服务营业场所名录查询」** |
| 链接 | <https://zwfw.spb.gov.cn/sj/350000/pfyycsml>（省份代码替换为对应值） |
| 要求 | **注明来源与获取日期**（`place.source` / `place.source_fetched_at` 与 `post_office` 的同名列即为此而设） |
| 覆盖范围 | ⚠️ **只含普遍服务营业场所**（支局 / 邮政所） |

⚠️ **两个必须知道的数据边界**：

1. **不含主题邮局、风景戳网点、代办所、快闪邮局。** 这几类在全球范围内**都没有官方名录**，
   只能靠用户共建（UGC）。如果你关注它们，那些条目是由使用者自己录进去的，
   不是从任何官方来源抓来的 —— 请据此判断可信度。
2. **不含邮政编码。** 邮编需要另外按行政区划代码关联。

## 三、邮票

### 元数据（志号、面值、齿孔度数、版别、防伪方式……）

| 项 | 内容 |
| --- | --- |
| 来源 | **国家邮政局**逐套发布的纪特邮票发行公告 |
| 链接 | <https://www.spb.gov.cn/gjyzj/c100040/> |
| 要求 | **注明来源** |

这是本项目最有价值的一手数据源：它同时给出了**齿孔度数 / 印刷版别 / 防伪方式**，
而这三项恰好是"同图不同版别"判别所需的元数据。

> 换句话说：**版别判定不靠视觉，靠这份结构化元数据做硬过滤**
> （见 `docs/need/01` §3.7 的结论修正）。

### 邮票图片 ⚠️

| 项 | 内容 |
| --- | --- |
| 来源 | **使用者自行扫描** |
| 许可 | 你自己扫描的图片，归你自己处置 |
| ❌ 明确不使用 | **中国集邮有限公司**（`cpi.chinapost.com.cn`）的邮票图片 |

**为什么不用它**：该站页面底部明确写着

> 「本网站内容未经书面许可不得转载、摘录、镜像」

这是**明确的禁止性声明**，不是模糊地带。因此：

- ❌ 不抓取它的图片
- ❌ 不把它作为"生成邮票"的素材来源
- ✅ 改用**你自己扫描的票图** —— 而且这本来就是更优选择：
  你自己的票分辨率更高、色彩更真实，并且正是"以图搜票"检索所依赖的底库
  （同一枚票在你的收藏里会反复出现，第一次人工确认之后即可自动命中）。

## 四、邮票目录（可选接入）

| 项 | 内容 |
| --- | --- |
| 来源 | **Colnect CAPI** |
| 帮助 | <https://colnect.com/en/help/capi> |
| 申请 Key | <https://colnect.com/en/capi/apply_for_key> |
| 费用 | 基础 Key 免费申请（个人项目可获批）；**以图搜票按次计费**，需单独开通 |
| ⚠️ 硬性要求 | **必须署名（attribution required by Colnect）** |
| ⚠️ 技术限制 | 站点部署了 Anubis 反爬 —— **网页抓取会被主动阻断**，必须走官方 API |

**不填 Key 会怎样**：不会怎样。本项目默认**完全离线可用**，Colnect 只是让邮票字段
更容易填准。关掉它只会降低精度，不会让任何功能不可用。

### 其他邮票目录：**均无官方 API**

StampWorld、Michel、Scott、Stanley Gibbons —— 经调研确认**都没有公开 API**，
不构成可用数据源。请不要为它们写抓取器。

## 五、署名：怎么落实

你的实例**自己用**时，署名不是义务；但**一旦分发数据包或公开部署**，就必须署名。

建议在数据包内附带一个 `ATTRIBUTION.txt`，内容形如：

```
本数据包包含以下第三方数据，各自许可如下：

* 行政区划（全球）
  来源：GeoNames — https://www.geonames.org/
  许可：Creative Commons Attribution 4.0 (CC-BY 4.0)
  获取日期：YYYY-MM-DD

* 行政区划（中国）
  来源：中华人民共和国民政部 / 国家统计局
  整理：modood/Administrative-divisions-of-China
  获取日期：YYYY-MM-DD

* 邮局名录
  来源：国家邮政局「邮政普遍服务营业场所名录查询」
  获取日期：YYYY-MM-DD

* 邮票元数据
  来源：国家邮政局纪特邮票发行公告
  获取日期：YYYY-MM-DD

* 邮票目录（如启用）
  来源：Colnect — https://colnect.com/
  获取日期：YYYY-MM-DD
```

> 数据库里已经为此预留了字段：`place.source` / `place.source_fetched_at`
> 与 `post_office` 的同名字段。**导入脚本应当填写它们** ——
> 这样"这份数据是哪天从哪来的"永远查得到，不依赖这份 README 被同步更新。
