# 识别确认界面 · 最小可看版（frontDemo）

## 怎么打开

**双击 `index.html`。** 不需要 WSL、不需要起服务、不需要 npm、不需要网络。

`template.html` 里没有数据（它是模板），**直接打开它是空白页** —— 这是有意的：
数据由 `generate.py` 从真实识别结果生成后内联进 `index.html`。

## 这文件夹里有什么

| 文件 | 作用 |
| --- | --- |
| **`index.html`** | **你要打开的那个**。自包含（CSS/JS/数据都在里面），只引用 `images/` |
| `template.html` | 界面的模板（源码）。改界面改这个，然后重新生成 |
| `generate.py` | 跑真实管线 → 生成数据 + 预览图 → 渲染出 `index.html` |
| `validate.py` | 不开浏览器也能做的检查（数据可解析、图片齐、无 `</script>` 冲突…） |
| `_check_overlay.py` | 把界面要画的叠加**用 Python 重画一遍**，用来肉眼核对坐标对齐 |
| `images/` | 4 张页面预览（工作尺度，与四边形坐标同一空间） |
| `_check/` | 上面那个脚本的产物。**建议看一眼 `_check/p005_overlay.jpg`** —— 它暴露了一个真问题（见下） |

重新生成（在 WSL 开发环境里）：

```bash
export PMTRIP_OCR_ENGINE=rapidocr
python docs/frontDemo/generate.py
python docs/frontDemo/validate.py .
python docs/frontDemo/_check_overlay.py .
```

## 数据是**真实识别结果**，不是编的

`generate.py` 把 `recognize_page` 的输出原样导出：`quad` / `circle` /
`decision` / `reason` / `queue` / `ocr_lines` / `stage_notes`。
所以界面上看到的问题**都是真的问题**。

四个样本各有用途：

| 样本 | 演示什么 |
| --- | --- |
| `p005`（9 张卡整页） | 「整页折叠成摘要 + 只让可疑卡自动展开」；卡是**倾斜**的，所以四边形比轴对齐框准 |
| `ink_too_much`（墨太多） | **真实失败**：圆定位落在明信片印刷抬头「中国邮政 CHINA POST 邮戳卡」上 |
| `closeup_1`（特写-1） | **词表防线**：OCR 给地名「福建南火」**置信度 0.90** 但是错的 —— 只看置信度会显示成可信 |
| `dark_single`（深色垫底单卡） | A1 用的那类样本；用来对比"一页全绿时能多快扫完" |

## 界面上的三个设计事实（都有实测理由）

1. **颜色只按 `decision`，不按 `confidence`** —— 因为「福建南火」置信度 0.90 却是错的。
   绿色只给"高置信度 **且** 在词表里"（开放文本字段）。
2. **画四边形而不是矩形** —— 卡可能倾斜（`p005` 底行就是），bbox 画不准。
3. **画邮戳圆** —— 这是**最难从字段值看出来**的失效模式。本页就抓到了：
   见下面「它已经发现的真问题」。

## 底栏的点击计数器

它把 A5 的意义直接摆出来：**「看」的量两种方式一样，差别在必须点几次。**

* **逐卡确认** = N 张卡 → **N 次**确认动作（即使全对也要走完 N 个循环）
* **整页确认** = N 张卡 → **1 次**

字段修改次数两种方式**完全一样**，计数器没有把它重复计一遍。
点两个按钮会弹出说明，包括整页方式的风险（一键确认会削弱"每个值都被看一眼"，
所以本界面只让可疑项自动展开，用颜色当注意力路由）。

## 它已经发现的真问题（这就是做这个界面的价值）

### 1. 坐标系混用（已修）

第一版把所有卡的圆**全部画在页面左上角** —— 因为 `verdict.circle` 是**卡局部**
坐标（`classify_postmark` 跑在正射图上），而界面画在**整页**上。
7 张卡的圆因此完全重叠。

这个错**不报错**，只是看起来"圆检测很乱"，很容易被误判成检测器不好。
修法：在**管线里**填好 `CardResult.circle_page`（不是放在 API 路由里 ——
第一版放在路由里，另一个消费者静默地保留了 bug，重新生成的叠加图与修复前**逐字节相同**）。

### 2. ⚠️ 圆抓到了**邮票的圆形图案**，不是邮戳（**未修，待处理**）

修好坐标后，叠加图直接显示出来（见 `_check/p005_overlay.jpg`）：

| 卡 | 圆实际落在 |
| --- | --- |
| 3 / 4 / 6 | **邮票上的圆形图案** |
| 1 / 2 / 5 | **空白处** |
| 0 | 勉强碰到邮戳 |

**连"只有邮票、没有邮戳"的卡 5 都报了一个圆。**

这说明 `find_postmark_circle` 在多卡整页的卡裁剪图上，**优先找到了邮票里那个
圆形的球体图案**（10分/30分邮票上确实有一个圆形地球图案），而不是 25mm 的邮戳环。

**这个问题在字段值上几乎看不出来** —— 只有把圆画出来才看得见。
它是当前最值得处理的一项：戳型判别与文字区域提取都依赖这个圆。

## 已知的取舍

* 预览图是**工作尺度**的（`recognize_page` 缩放后的），因为四边形与圆的坐标
  就在那个空间里。用原图会让叠加整体错位。
* 词表按样本**真值**配置，好让"词表那道防线"在界面上看得见 ——
  这不是造假，它演示的正是"字典填好之后会怎样"。每一页的 `demo_note` 说明了这点。
* 云端默认**关**（花钱、结果不可复现），所以这里全部是本地识别结果。
