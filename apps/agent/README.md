# `pmtrip-agent` — 本地扫描 Agent

一个单文件、零依赖的扫描驱动程序。**它必须跑在「USB 线插着扫描仪的那台机器」上。**

> **为什么不能跑在服务器上**：USB 扫描仪**没有 IP 地址**，它不是网络设备。
> 因此任何跑在别的机器上的服务都不可能"通过网络选择它"——网络上根本不存在这个设备。
> 详见 [`docs/need/04-决策终局与遗留问题.md`](../../docs/need/04-决策终局与遗留问题.md) §四。

---

## 数据流

```
浏览器（Windows）                     pmtrip-agent（Windows）        Linux 服务器
    │  ① 点「扫描」                          │                          │
    ├──── ② POST localhost:18080/scan ──────▶│                          │
    │                                        ├─ ③ WIA 驱动扫描仪 → 取图  │
    │◀─────── ④ 图像字节直接返回 ─────────────┤                          │
    │                                                                   │
    └──── ⑤ POST /api/assets（复用「手工上传」的同一套 API）─────────────▶│
                                                          分割 / 识别 / 入库
```

**关键设计：Agent 不持有任何凭据，也不上传到服务器。**

这样做的理由：
- 浏览器已经是登录态，复用已有的上传端点 → **服务端不需要新增任何 API**
- Agent 因此只是一个「本机外设驱动」，没有可泄露的密钥
- 少一条认证路径，就少一处可能出错的地方

## 🔒 安全边界

| 机制 | 作用 |
| --- | --- |
| **默认只绑 `127.0.0.1`** | 只有本机进程/页面能连上 |
| **`--origin` 白名单** | ★ **真正的安全边界**：决定哪个本机页面能**读到**扫描结果 |

**为什么 CORS 白名单如此重要**：Agent 只监听回环，所以只有本机页面能访问它。
但如果不设白名单，**任意网页**（你随手打开的一个页面）都能：
1. 触发一次扫描（消耗耗材、占用设备）
2. **读取扫描结果**——把你的邮戳卡图像上传到攻击者的服务器

所以：

```bash
# ✅ 正确：只放行你自己的服务器地址
pmtrip-agent --origin http://192.168.1.10:9999

# ❌ 危险：等于让任意网页都能驱动扫描仪并取走图像
pmtrip-agent --origin '*'
```

未指定 `--origin` 时程序会**明确警告**，而不是静默失败。

**如果确实需要暴露到局域网**（例如服务器在另一台机器上，需要服务器主动调用 Agent），
必须同时设置 `--token`，并且接受"监听地址不是回环"的风险提示。

## 构建

不需要本地 Go 工具链 —— 用 Docker：

```bash
# Windows 可执行文件（给用户的机器用）
docker run --rm -v "$PWD":/app -w /app -e GOOS=windows -e GOARCH=amd64 \
  golang:1.23-alpine go build -ldflags "-s -w -X main.version=0.1.0" \
  -o pmtrip-agent.exe ./cmd/pmtrip-agent

# Linux（用于把 USB 线插到 Linux 机器的场景）
docker run --rm -v "$PWD":/app -w /app -e GOOS=linux -e GOARCH=amd64 \
  golang:1.23-alpine go build -ldflags "-s -w" -o pmtrip-agent ./cmd/pmtrip-agent
```

产物是**单个静态二进制**，拷到目标机器双击/直接运行即可 ——
用户机器上**不需要 Python、Node 或任何运行库**。这是选 Go 而不是 Python 写这个组件的全部原因。

## 用法

```bash
# 排查：列出设备
pmtrip-agent -list

# 正常运行
pmtrip-agent --origin http://192.168.1.10:9999

# 详细日志
pmtrip-agent --origin http://192.168.1.10:9999 -v
```

### 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--addr` | `127.0.0.1:18080` | 监听地址。**非回环会告警** |
| `--origin` | 空 | 允许的网页来源，逗号分隔。**不设则浏览器读不到结果** |
| `--token` | 空 | 可选口令（仅暴露到局域网时需要） |
| `-list` | — | 只枚举设备然后退出 |
| `-v` | — | 调试日志 |

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/health` | `{ok, backend, version, devices, error?, hint?}`。**不需要 token** |
| `GET` | `/devices` | `{devices: [{id, name, capabilities}]}` |
| `POST` | `/scan` | 请求体是 `ScanRequest`，**响应体直接是图像字节** |

```jsonc
// POST /scan 的请求体
{
  "device_id": "",          // 留空 = 第一台设备
  "dpi": 600,               // 默认 600
  "color": true,            // 彩色必须开：邮戳的油墨颜色本身是记录对象
  "source": "flatbed",      // flatbed | adf | adf_duplex
  "format": "jpeg"          // jpeg | png | tiff
}
```

响应头会带 `X-Scan-Backend` 与 `X-Scan-DPI` 便于排查。

## 平台后端

| 平台 | 后端 | 实现方式 |
| --- | --- | --- |
| **Windows** | **WIA** | 调 `powershell.exe -File` 执行一段内嵌的 WIA COM 脚本 |
| **Linux** | **SANE** | 调 `scanimage`（`sane-utils` 包） |
| macOS | — | 明确返回"不支持"，**不静默降级** |

**为什么用命令行工具而不是链接 SDK**：

| 取舍 | 说明 |
| --- | --- |
| ✅ 换来 | 单一静态二进制、无需 cgo、交叉编译简单、不需要厂商 SDK 与运行库 |
| ❌ 代价 | 每次调用多几十毫秒的进程启动 —— 对**手动触发**的扫描完全无所谓 |

这与 [`docs/ok/04`](../../docs/ok/04-环境约束与多语言架构选型.md) §3.4
「不引入 cgo / Rust 以控制运维复杂度」的判断一致。

**同一个 WIA 后端顺带解决了另一个问题**：`docs/ok/04` §2 讨论过的
"sane-airscan 在 M1136 上用不了"（USB-only、无 eSCL）。走 Windows 侧的 WIA
完全绕开了 Linux 驱动的不确定性。

## 刻意不做的两件事

1. **不探测图像宽高与 DPI** —— 服务端入库时用 Pillow 读。这样 Go 侧不需要引入
   图像解码依赖，二进制保持小。`Result` 里保留字段是为了将来需要时能填。
2. **不做多页批量** —— `Scan` 只负责一页，多页由调用方循环。
   ADF 机型（不是当前这台 M1136）在 v1.1 之后再说。

## 扫描参数建议

| 项 | 建议 | 理由 |
| --- | --- | --- |
| 分辨率 | **600 dpi** | 实测日戳小字 5 mm、风景戳 3 mm；600 dpi 下最小字高约 71 px，已够 OCR。1200 dpi 只有边际收益且慢得多 |
| 色彩 | **彩色（必开）** | 彩色戳的颜色本身就是记录对象，灰度化会丢信息 |
| 增强选项 | **全部关闭** | 自动纠偏/去背/锐化会破坏油墨边缘信息 |
| 垫底 | **深色卡纸** | 不是优化技巧，是切分方案成立的前提 |

更完整的说明见 [`docs/ok/05-部署架构与安装指南（规范）.md`](../../docs/ok/05-部署架构与安装指南（规范）.md) §六。
