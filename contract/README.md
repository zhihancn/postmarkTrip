# `contract/` — 契约层

这个目录是**跨模块唯一的共享事实**。它存在的原因只有一个：

> 前端渲染（TypeScript/Konva）与服务端渲染（Go，v1.2）必须视觉一致，但**不能靠"用同一个语言同一个库"来保证一致**——那会让两个模块被迫绑在一起演化。

一致性由**同一份 JSON Schema + 可执行的黄金图像回归测试**保证。这样每个模块才能各自用最合适的语言独立演化。

---

## 目录

```
contract/
├── scene.schema.json     卡片场景图（「模板」的唯一定义）
├── error.schema.json     统一错误结构
├── README.md             本文件
└── gen/                  由 schema 生成的各语言类型
    ├── types.ts
    ├── types.py
    └── types.go
```

## 硬规则

| # | 规则 |
| --- | --- |
| 1 | **依赖必须无环。** `web` 与 `agent` 只能通过 **HTTP** 调用 `api`；三者都可以依赖 `contract/` 的**生成类型**。 |
| 2 | **任何模块不允许 import 另一个模块的源码。** |
| 3 | **`gen/` 下的文件必须由 schema 生成，不允许手工编辑。** 手工维护三份类型 = 三处必然漂移。 |
| 4 | **破坏性变更必须递增 `schema_version`。** 渲染器遇到不认识的版本必须**拒绝渲染**，而不是尽力而为。 |
| 5 | **所有长度用毫米，角度用度。** 像素只在栅格化那一步出现（`px = mm / 25.4 × dpi`），且不得回流进布局计算。 |

## 生成

```bash
make gen-contract
```

生成器在容器里跑，**宿主机不需要装 Node / Python / Go 之外的东西**（实际上连这些也不需要）。

生成计划：

| 目标 | 工具 |
| --- | --- |
| `gen/types.ts` | `json-schema-to-typescript` |
| `gen/types.py` | `datamodel-code-generator` |
| `gen/types.go` | `go-jsonschema` |

> **状态（v1.1 M1，2026-10-21）**：渲染器已经落地
> （`apps/web/src/render/`，Canvas 2D），消费的就是这份 schema。
> 但 `gen/` 与本文件列出的生成脚本**还没有落地** —— 目前 TypeScript 类型手写在
> `apps/web/src/shared/types.ts`，与 schema 对齐由测试和 `tools/check_web_static.py` 兜底。
> 这违反了下面的规则 3，是**有意记录的欠账**：等第二个渲染实现（v1.2 的服务端渲染器）
> 出现时必须改成生成，否则两份类型必然漂移。
> 像素级黄金图像测试也还没做（本环境无无头浏览器）；当前用「布局计划测试」代替，见
> `apps/web/tests/scene.test.mjs`。

## 黄金图像回归测试

```
tests/contract/
├── fixtures/    场景 JSON（输入）
└── golden/      期望渲染结果 PNG（基准）
```

**流程**：加载 fixture → 用**每一个渲染实现**渲染 → 与 `golden/` 做像素差异比对 → 超过阈值即失败。

**这个测试的价值随时间增长**：

| 阶段 | 渲染实现 | 测试的作用 |
| --- | --- | --- |
| v1.0 / v1.1 | 只有前端 | 防止前端渲染逻辑被无意改动 |
| v1.2 | 前端 + 服务端 | **自动成为两者的对账机制**，不需要重写任何逻辑 |

阈值会区分两类差异：**结构性差异**（元素位置/尺寸/图层，容忍度极低）与**抗锯齿差异**（不同栅格化器的固有差别，容忍度放宽）。具体数值在引入第二个渲染器时标定。

## 为什么 `scene.schema.json` 里有这些看似多余的字段

| 字段 | 为什么必须有 |
| --- | --- |
| `slot.z` | 真实邮戳是**骑缝压在邮票上**的（`docs/need/03` §三.6）。没有图层顺序就做不出正确的电子卡 |
| `PostmarkSlot.source` | 区分「从扫描件抠出的位图（事实）」与「参数化生成（美化）」。前者日期烤死在像素里，后者才能隐藏/替换日期 |
| `StampSlot.preserve_perforation` | 齿孔是邮票的鉴伪特征，默认不裁切——这与「邮票识别要靠元数据而非视觉」是同一套思路（`docs/ok/03` §2.2） |
| `TextSlot.writing_mode` | 中文邮戳的名称与书法**常为竖排**（`docs/need/03` §三.3 实测） |
| `canvas.bleed_mm` | 屏幕欣赏场景为 0；保留它是为了将来若要印刷时契约不必破坏性变更 |
| `Mm` 允许负值 | 出血、故意越界摆放是合法的排版手段 |
